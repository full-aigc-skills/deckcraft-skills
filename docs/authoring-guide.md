# 技能作者指南

## 1. 结构与披露

计划每个技能由 `SKILL.md`、本技能 `references/` 和必要的 `examples/` 组成；确定性检查确需脚本时才增加 `scripts/` 与行为测试。
SKILL.md 小于 500 行，frontmatter 的 name 与目录一致，description 写“何时激活”。主入口保留授权点、失败边界和验收，详细命令按需读取。
跨技能按名称交接，不能通过 `../兄弟技能/` 链接读取资源。目录存在不代表单独安装后资源存在。

## 2. 每项操作合同

记录输入、前提、运行时发现、动作、副作用、返回结果、错误、恢复和验收。标明 Headless/Remote，区分 slide points 与屏幕坐标。
写入说明要覆盖输出目录和覆盖策略；不确定的修改结果先回读文稿或请用户核对。不要把 upstream panic guard 描述成会话事务，也不把命令 enabled 描述成用户权限。

## 3. 维护门禁

- 命令覆盖表对照实际 `commands` 输出：每条命令有操作归属，缺口明确列出。
- 在孤立目录模拟只安装一个技能，验证其所有文件链接与脚本资源。
- lint 检查名称、触发、行数、链接；TRACE 作为静态质量辅证，不代替场景执行。
- 场景回归包含触发、拒绝误触发、缺工具、未知写入、损坏状态和格式降级。
- 示例程序在当前声明版本下执行后才能标记已验证；保留输入、输出摘要和源码身份。

## 4. 与插件协作

技能库发布原始技能，插件可固定并打包经过验证的子集；禁止直接手改同步后的技能内容。分发检查应覆盖来源、路径和资源完整性。
本轮不创建这些脚本、测试或锁文件；实现门禁见验证矩阵。
